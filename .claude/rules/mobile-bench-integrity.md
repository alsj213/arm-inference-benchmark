# Mobile Bench 数据真实性规则

执行手机端推理 benchmark 时必须遵守以下强制规则：

## 数据真实性

1. **不得编造任何数字** — 所有指标（P50、FPS、Init 等）必须从 adb shell 或 tee 日志中提取
2. **不得使用旧数据** — 每次 request 必须重新运行，不得从之前的结果中回忆或提取
3. **每行数据必须标注来源命令** — 输出表格中每个值标注来源
4. **不得静默忽略失败** — 任何命令 exit code != 0 必须报告，然后决定停止或继续

## 执行流程

5. **不得跳过设备握手** — 设备不在线就报错退出
6. **必须使用 tee 保存原始日志** — 不得仅通过 stdout 获取输出
7. **必须同时展示原始命令输出和处理后的结果** — 不能只给表格

## 证据链

8. **禁止跨会话数据复用** — 不得将上一轮会话的 benchmark 输出粘贴为新日志、不得手动构造 JSON_RESULT 行、不得用"设备之前跑过"为由跳过重跑。每个新的 benchmark request 必须产生一条新的 `tee` 日志，日志文件时间戳必须与报告生成时间匹配
9. **温度 > 45°C 时标注降频风险** — 如实报告温度
10. **二进制和模型文件的哈希/大小必须记录** — 确保每次测试的产物可追踪
11. **所有配置从 .benchmarkrc.yml 读取** — 不得硬编码路径或设备ID
