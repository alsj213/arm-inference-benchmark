# MNN vs TVM GEMM 性能探究总结

> 骁龙 865 (SM8250) / FP32 / 2026-06-10
> 分支: feat/gemm-pack-analysis · 10 个方阵 GEMM 实测

---

## 0. 测试条件

| 条件 | 设置 | 说明 |
|------|------|------|
| 设备 | 红米 K30 Pro (M2007J3SC) | 骁龙 865, 8核 (4×A55 + 3×A77@2.4G + 1×A77@2.84G) |
| 绑核 | `taskset 80` 绑定 **CPU7** (A77 大核) | 所有线程限制在 CPU7，避免大小核迁移 |
| 线程 | MNN `CPUMatMul` 强制 `mSupportMultiThread=false` | 源码修改，消除内部多线程穿透 |
| 频率 | 未锁频 (无 root) | 频率可能在 844MHz-2.84GHz 间波动 |
| 精度 | FP32 | |

| MNN 编译 | Release, OpenCL=OFF | ARM NEON 汇编路径 |
| TVM 编译 | Relay build `opt_level=3`, LLVM `-mcpu=cortex-a77` | GraphExecutor 运行时 |
| 预热/测试 | 小矩阵 warmup=20/runs=200; 大矩阵 warmup=3/runs=10 | |

## 1. 探究内容

本次围绕 **GEMM (矩阵乘法)** 算子，从四个维度拆解 MNN 和 TVM 的性能差异：

| 维度 | 方法 | 工具 |
|------|------|------|
| **端到端延迟** | 10 个方阵 (16→8192) 双框架实测 | `single_op_benchmark` |
| **调度开销** | CPU 周期模块级采样 | `simpleperf record -g` |
| **纯计算效率** | 剥除调度开销后的 GEMM 算力 | simpleperf + GFLOPS 计算 |
| **分块策略** | 源码级对比 | TVM topi/x86 + MNN CPUMatMul |

## 2. 端到端性能：10 个方阵实测

> 条件: `taskset 80` CPU7 + MNN 强制单线程

| Shape | FLOPs | MNN(ms) | TVM(ms) | TVM/MNN | 胜者 |
|-------|------:|--------:|--------:|:-------:|:--:|
| 16² | 8K | **0.001** | 0.010 | 10.0x | 🟠 MNN |
| 32² | 65K | **0.003** | 0.012 | 4.0x | 🟠 MNN |
| 64² | 524K | **0.016** | 0.026 | 1.6x | 🟠 MNN |
| 128² | 4.2M | **0.111** | 0.135 | 1.2x | 🟠 MNN |
| **256²** | **33M** | 0.888 | **0.623** | **0.70x** | 🔵 TVM |
| **512²** | **268M** | 6.606 | **2.807** | **0.42x** | 🔵 TVM |
| **1024²** | **2.15B** | 50.2 | **20.3** | **0.40x** | 🔵 TVM |
| **2048²** | **17.2B** | 353.1 | **167.4** | **0.47x** | 🔵 TVM |
| **4096²** | **137B** | 2463.9 | **1779.2** | **0.72x** | 🔵 TVM |
| **8192²** | **1.1T** | 31837 | **25910** | **0.81x** | 🔵 TVM |

**TVM/MNN 比值收敛: 10.0x → 0.40x。交叉点在 128→256。大矩阵 TVM 快 1.2x-2.5x。**

---

## 3. 调度开销：simpleperf 模块级实证

对 64²（小矩阵）和 4096²（大矩阵）做 CPU 周期采样：

| 模块 | MNN 64² | TVM 64² | MNN 4096² | TVM 4096² |
|------|:------:|:------:|:--------:|:--------:|
| **框架计算 (.so)** | **34.4%** | **4.9%** | **97.8%** | **93.6%** |
| **调度 (benchmark)** | **0.8%** | **26.6%** | **1.6%** | **5.5%** |
| libc (memcpy) | 3.6% | 40.4% | 0.4% | 0.9% |
| linker | 59.6% | 26.4% | 0.2% | 0.1% |

**根因**：MNN 用 vtable 直接跳转（~3μs/次），TVM 用 PackedFunc 类型擦除（~32μs/次）。小矩阵时 TVM 的 26.6% CPU 消耗在类型检查/参数打包上，实际计算仅占 4.9%。

---

## 4. 纯计算效率

用 4096² 的 simpleperf 数据剥除调度开销：

| | 总时间(ms) | 计算占比 | 纯计算时间(ms) | **纯计算 GFLOPS** |
|---|:---:|:---:|:---:|:---:|
| MNN | 2463.9 | 97.8% | 2409 | ~57 |
| TVM | 1779.2 | 93.6% | 1665 | ~82 |

> 注: GFLOPS 超过单核理论值 (22.7G)，说明框架内部仍有部分多线程。taskset 限制了核迁移但未限制线程数。相对比值 (TVM/MNN=0.72x) 仍然有效。

---

## 5. 分块策略对比

| | MNN | TVM |
|---|------|------|
| 分块大小 | **固定** eP=12, hP=8 (96 元素) | **自适应** (64→256 per dimension) |
| 决定方式 | 编译时硬编码 | LLVM 查询 `-mcpu=cortex-a77` 的 cache 参数 |
| 数据复用次数 | 8 次 (micro-kernel 内) | 128 次 (tile 内) |
| 设计哲学 | 一次编译，处处运行 | 按目标 CPU 编译，极致性能 |

## 6. 与之前未绑核数据的对比

```
TVM/MNN 比值变化 (越小 TVM 越好):

          之前(无绑核)    现在(taskset CPU7)
16²         32.0x   →      10.0x
64²          6.6x   →       1.6x
128²         3.1x   →       1.2x
256²         1.84x  →       0.70x   ← 交叉点提前
512²         1.15x  →       0.42x
1024²        0.78x  →       0.40x
2048²        0.74x  →       0.47x
4096²        0.80x  →       0.72x
8192²        0.73x  →       0.81x
```

之前未绑核时大小核混跑，MNN 受益于私下多线程导致数据虚高。绑核后 TVM 优势更明显——交叉点从 512→1024 提前到 128→256。

---

## 7. GPU 探索

MNN OpenCL 在 Adreno 650 + Android 12 上存在 SIGSEGV 兼容问题（MTE tagged pointer），未能完成 CPU/GPU 实测对比。`onExecuteEnd` 缺少 `clFinish` 同步的问题已定位并提交修复。

---

## 8. 结论

> **MNN 胜在零开销调度（vtable 直调），TVM 胜在自适应编译优化（LLVM 感知 cache 参数）。正确绑核后交叉点在 128→256，大矩阵 TVM 快 1.2x-2.5x。**

### 选型速查

| 场景 | 推荐 | 理由 |
|------|:----:|------|
| 移动端 CV (MobileNet 等小模型) | **MNN** | 小算子多，低 overhead 碾压 |
| 大 GEMM / 大 Conv | **TVM** | 自适应分块释放显著算力优势 |
| LLM Decode (单 token, M=1) | **MNN** | 延迟敏感，调度开销致命 |
| LLM Prefill (大批次) | **TVM** | 大批次 GEMM，算力优先 |
